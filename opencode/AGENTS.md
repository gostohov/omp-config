# General Instructions

## Environment

- Ты работаешь в WSL (Windows Subsystem for Linux).
- Команды выполняются внутри WSL.
- Файлы Windows доступны через `/mnt/c`.
- Имя Windows-пользователя `gostokhovza`
- `gostokhovza` не обладает админскими правами
- Имя Windows-машины в локальной сети НСПК разрешается через DNS как
  `vdi03199.nspk.ru`.
- Windows-хост доступен как `vdi03199.nspk.ru`, но не заменяй этим адресом
  `localhost` или `127.0.0.1` без проверки владельца процесса, сетевого
  интерфейса и фактического binding.
- Всегда отвечай на русском языке.

## Current date

- Для запросов об актуальной, последней или недавно изменившейся информации
  определяй текущую дату по системному времени WSL, а не по памяти модели.
- Перед добавлением года в поисковый запрос проверь его командой `date +%Y`.
- Не используй в поисковых запросах прошлые годы как текущие.
- Не добавляй год в запрос без необходимости: он может скрыть релевантные
  страницы и документацию предыдущих лет.

## Source selection

Перед использованием инструментов внутренне определи тип задачи, не выводя
эту классификацию пользователю:

- `LOCAL` — ответ полностью определяется локальным репозиторием или
  предоставленными пользователем материалами.
- `INTERNAL` — задача обращается к защищённому ресурсу `nspk.ru`,
  `*.nspk.ru`, `mir.ru` или `*.mir.ru`.
- `EXTERNAL` — нужны актуальные или сторонние сведения.
- `MIXED` — локальную реализацию нужно сопоставить с внешней документацией.

Правила:

1. Для `INTERNAL`-задач не используй SearXNG, `webfetch` или другие обычные
   HTTP-инструменты. Следуй разделу NSPK.
2. Если пользователь передал конкретный публичный URL, сначала прочитай его
   через `searxng_web_url_read`. Используй поиск, если страница недоступна или
   нужен дополнительный контекст.
3. Для остальных `EXTERNAL`-задач сначала используй
   `searxng_searxng_web_search`, затем прочитай 1–3 релевантных источника через
   `searxng_web_url_read` и только после этого формируй ответ.
4. Для `MIXED`-задач:
   - изучи локальные файлы, чтобы определить версии, API и сообщения ошибок;
   - затем обязательно выполни поиск через `searxng_searxng_web_search`;
   - прочитай 1–3 релевантных источника через `searxng_web_url_read`.
5. Самостоятельно выбирай `EXTERNAL` или `MIXED`, не спрашивая разрешения
   пользователя, если ответ зависит от:
   - актуальной или недавно изменившейся информации;
   - версий, релизов, совместимости или документации библиотек и продуктов;
   - неизвестной ошибки, технологии, термина или поведения внешней системы;
   - сравнения, рекомендации или проверки факта;
   - содержимого публичного URL, которого нет в текущем контексте.
6. Не считай локальный код источником истины для:
   - поведения сторонних библиотек и сервисов;
   - актуальных версий и документации;
   - deprecated API и breaking changes;
   - известных ошибок и уязвимостей;
   - текущих рекомендаций.
7. Наличие правдоподобного ответа в коде не отменяет внешнюю проверку.
8. Предпочитай официальную документацию и первичные источники.
9. Для внешних утверждений прикладывай прямые ссылки.
10. Не завершай `EXTERNAL`- или `MIXED`-задачу, пока не попытался выполнить
    внешний поиск или прочитать переданный пользователем публичный URL. Если
    нужный инструмент недоступен, явно сообщи об этом пользователю.

## Browser routing

- Используй `searxng_searxng_web_search` для поиска публичных источников.
- Используй `searxng_web_url_read` для чтения конкретных публичных страниц.
- Используй `webfetch` только как запасной вариант, если
  `searxng_web_url_read` недоступен или не смог прочитать страницу.
- Для интерактивных, динамических и авторизованных страниц сначала загрузи
  skill `playwright-cli` и следуй его инструкциям.
- Не устанавливай и не запускай отдельный Playwright внутри WSL.
- Не подключайся к браузеру заранее: используй его только когда задача
  действительно требует браузерного взаимодействия.
- Для `INTERNAL`-URL применяй правила раздела NSPK.

## Dependencies

- Не искать решение в `node_modules` по умолчанию и исключать эту директорию
  из широкого поиска по проекту.
- Сначала изучить исходный код проекта, `package.json`, lock-файл, конфигурацию,
  сообщения ошибок и официальную документацию зависимости.
- Обращаться к `node_modules` только как к последнему средству, когда проблема
  зависит от фактической реализации конкретной установленной версии пакета.
- В таком случае читать только конкретный пакет и объяснить, зачем
  потребовалось исследование его реализации.
- Никогда не изменять файлы внутри `node_modules`.

## NSPK

- URL с hostname `nspk.ru`, `*.nspk.ru`, `mir.ru` или `*.mir.ru` считай
  `INTERNAL`.
- Для работы с такими страницами загрузи skill `playwright-cli`.
- Не используй для них SearXNG, `webfetch` и другие обычные HTTP-инструменты.
- Используй только вручную открытый авторизованный Windows Chrome.
- Не читай и не раскрывай `.env`, credentials, cookies, токены, заголовки
  авторизации и данные браузерного профиля.
